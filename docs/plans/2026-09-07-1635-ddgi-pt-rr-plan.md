## Context and requested result

The owner requests RTXGI integration, explicitly requiring probes to be created
automatically and follow the camera from the first working version. No fixed,
manually authored volume milestone. Keep hybrid raster + RTXDI + DDGI as the
main renderer, restore true camera-ray path tracing as an optional comparison
mode, share geometry/material/light data, and restore DLSS Ray Reconstruction
as an option beside NRD with discoverable controls. Retain ordinary DLSS SR.

The owner's PT request supersedes the earlier removal-only PT direction. The
new optional algorithm is intentional product scope, not a compatibility rail.
Do not restore the deleted duplicate GLSL material compiler or old PT subclass.
No automated tests. Intermediate builds may be broken; final rendering must
work on the actual supported Vulkan device. Do not implement unrelated ECS,
world streaming, voxel geometry, foliage shadow architecture, NRC/SHaRC,
GPU-driven rasterization, new non-RT backends or stereo RT support.

## Approved decisions

1. Use RTXGI-DDGI 1.3.6 at `f33e496ca31b3f0eec1c4e2cbaa8bb620e337fa6`.
   Compile its shader math with the existing pinned Slang toolchain and execute
   through RenderingDevice; engine code owns allocations, dispatch and barriers.
2. Automatic nested scrolling grids per single-view render buffer, created
   when hybrid DDGI is active. Default proposal: four levels, 16^3 probes per
   level, spacing 2/4/8/16 world units, 128 rays/probe, one whole-level update
   per frame. These are starting settings, not measured performance presets.
   No authored volume Node/Resource or manual placement requirement.
3. Share RT geometry/BLAS/CLAS/TLAS, material programs and light tables. Add
   one shared native Slang hit-material path used by DDGI and PT. Preserve
   separate DDGI atlases, PT accumulation and camera RTXDI reservoirs.
4. Use a per-render-buffer RT coordinate origin, subtracting on CPU before
   float packing. Keep Node/physics world coordinates and raster SceneData
   conventions unchanged. This is limited rendering precision work required
   for camera-following probes and PT, not world-origin rebasing infrastructure.
5. True primary-camera-ray PT, with its own primary depth/motion/material guides.
   Use shared current BRDF and light semantics. Offer raw progressive reference
   accumulation without DDGI, denoising, TAA or frame generation, plus NRD/RR
   previews. Do not silently substitute raster-primary path tracing.
6. RR processes the composed noisy camera image and bypasses NRD. It does not
   replace DDGI probe integration. Hybrid supplies no fictitious reflection
   distance: omit optional specular-hit-distance/motion tags when no reflected
   signal exists. PT supplies valid reflection guides where available.
7. Expose renderer/DDGI/denoiser controls on Environment; keep existing
   Viewport/ProjectSettings scaling controls authoritative for resolution and
   DLSS quality. Show precise availability/configuration messages rather than
   silently replacing RR with SR. Verify the effective DLSS binary/model before
   claiming 4.5; a filename or preset letter alone is insufficient.
8. Support the current mesh/merged-MultiMesh/skinned/blend-shape RT material
   envelope and standard spatial/VisualShader material semantics within it.
   Unsupported procedural intersections, particle geometry, shader-driven
   vertex changes, alpha-blended materials and other existing diagnostic cases remain explicit.
   Do not claim full arbitrary Godot material/geometry or volumetric PT parity.

## Spatial state and scene coverage

`RendererSceneCull::_scene_cull` already gathers resident visible mesh and
MultiMesh receivers/casters independently of camera frustum/HZB/far range.
Reuse that current scenario population for DDGI and PT; do not revive the old
camera AABB gather or create a streaming subsystem. Preserve receiver/caster
layer semantics and identify view-layer changes as history invalidation.

Own DDGI cascade metadata/atlases under render-buffer RT state, not Environment
RID. Sharing one Environment across two mono viewports must not move each
other's probes or histories. Existing multi-view RT is unsupported: retain an
explicit rejection, never silently render eye zero. Do not infer stereo support
from the layout of generic scene buffers.

Carry scenario identity/generation into the RT history key or explicitly
invalidate the render buffer in `RendererViewport::viewport_set_scenario`
(`servers/rendering/renderer_viewport.cpp:1334`); that function currently does
not clear history, and RenderDataRD has no scenario RID. Camera identity alone
cannot protect against stale probes after a world swap. DDGI cell history is
independent of screen camera-cut/jitter history; preserve overlapping cells on
ordinary camera changes in the same scenario and configuration.

Each cascade tracks an int64 cell origin, modulo texture slot mapping and a
validity epoch. Update scroll mapping every frame independently of lighting
budget. Invalidate all entering slabs for arbitrary signed multi-cell moves;
nonoverlapping jumps reset every slot. Reset ray/history/relocation/classification
data consistently. New cells get priority, with bounded maximum update age so
constant travel cannot starve another cascade. No heap allocation proportional
to world travel and no full rebuild for a one-cell movement.

Validity is distinct from SDK active/inactive classification. Fresh slots may
trace/classify while excluded from lighting queries until initialized. Avoid
reading stale rays on unupdated levels. SDK blend/relocation/classification runs
only against current ray data for the selected level. Relocated probes must not
publish lighting sampled at their old location as if it were newly traced;
invalidate/retrace or preserve the matched position until its next valid update.
Inactive probes retain fixed-ray reactivation. Neighbor/cascade interpolation
must exclude invalid samples and renormalize; edge support and lack of any
support are defined, not extrapolated old light. Keep the SDK math as source,
using narrow recorded patches only if validity hooks cannot be provided externally.

Bound probe ray travel by the outer grid's diagonal, derived from counts and
spacing; document this finite GI reach independently of unrestricted camera
travel. The shadow leg follows current light visibility rules (directional
visibility is not clipped to the probe segment length). Default four levels
with one updated each frame imply 524,288 probe rays in a fully active level,
before shadow rays. Schedule dirty priority with weighted round-robin: every
active cascade gets an update within at most twice the number of cascades
in rendered frames at the minimum budget. This is a work bound, not an FPS claim.

The common RT origin applies consistently to AS instance translations,
previous/current motion transforms, analytic/projector/emissive light transforms,
camera reconstruction, probe descriptors and PT rays. Origin changes carry
previous-to-current basis offsets into temporal consumers or reset the affected
history; they do not move physical probe cell identity. Keep BLAS vertices local.
Never reconstruct huge absolute float positions and subtract afterward. Public
shader world-position builtins retain their documented meaning; do not silently
reinterpret them as RT-relative. Existing world-position material precision
limits must be distinguished from corrected AS/light/probe precision.

## Shared hit programs and PT contract

Extend the existing spatial Slang frontend to emit hit variants with explicit
intersection context, full normal/tangent decode, transformed TBN (including
negative/nonuniform scale), UV/color, view direction, geometric normal and
byte-offset uniform/bindless texture loads. Use ray-appropriate texture LOD/ray
footprints; never camera screen derivatives for probe rays. Supported generated
material expressions and VisualShader follow the same current material semantics.

Concretely extend `ShaderCompiler::_dump_slang_call` hit-context lowering;
implicit sampling uses ray-cone LOD, explicit textureLod/textureGrad retains
its supplied operands, and unsupported screen-dependent derivatives are
diagnosed. Complete material uniform packing for arrays/defaults/global and
instance data: existing allocation followed by one scalar pack is insufficient.
Extend the shared geometry ABI for UV2/CUSTOM attributes used by accepted
materials, closing CPU layouts and all raster/RT readers in the same step.

Decals are part of current raster material output, so support them in the same
hit-material contract. Reuse `storage_rd/texture_storage.{h,cpp}` DecalInstance,
DecalData and atlas; extend the existing Scenario volume gather with resident
RT decal RIDs instead of using only frustum-filtered `RenderDataRD::decals`.
Extract a shared position/normal/footprint evaluator from
`scene_forward_clustered.slang:1393–1459`. Pack RT-origin transforms alongside
the current view-space snapshot from the same source records; preserve masks,
sort order, camera-distance fades and atlas semantics for every consumer.
Preserve raster's actual reverse-bit cluster iteration ordering for overlapping
decals; a plain ascending RT list is not equivalent. Define identical capacity
admission for matching camera decals and retain a separate per-buffer RT
snapshot so broader offscreen gathering cannot overwrite the raster upload.
Start with bounded linear iteration over the resident decal snapshot; no new
spatial acceleration subsystem. Synchronize its generation/lifetime with materials.

Use native Slang raygen/any-hit/closest-hit/miss stages through existing RD RT
pipeline support. Material hit programs/table are shared by DDGI and PT pipelines;
raygen and output buffers remain distinct. SBT offsets must agree with every
pipeline's shared logical hit-group ordering. Do not share opaque shader-group
handle bytes across different pipelines: use one multi-raygen pipeline/SBT or
pipeline-local SBT allocations generated from the same material program table.
The existing RD API accepts multiple raygen shaders; this is a private layout
choice, not permission for a second material authority. Offsets also agree with every
TLAS instance/geometry including CLAS remapping. Share any-hit coverage with the
current DI visibility semantics; do not leave two material authorities. Preserve
surface generation identity and retire old SBT/program resources only after their
last GPU use. Unsupported material/topology is explicit in both modes.

DDGI hit radiance includes shared direct-light sampling, secondary emission,
environment miss and prior probe diffuse bounce feedback in unexposed scene
linear units. Do not copy sample `saturate`, double albedo/PI, use camera RTXDI
reservoirs, or import sample light/material tables. Probe relocation backface
classification distinguishes closed solids from supported double-sided surfaces.

PT traces primary rays and later bounces with shared BSDF/light PDF evaluation,
next-event estimation, MIS and Russian roulette. Use no DDGI feedback or camera
reservoir reuse in reference mode. Produce matching primary depth, normals,
albedo/specular guides, hit information, motion and emission; use previous
deformed positions/instance transforms, correct jitter and camera matrices.
Sky/miss/unlit semantics match the retained renderer. Preserve its explicit
alpha-blended-material diagnostic/exclusion in hybrid and PT: the baseline
only invokes pre/post-transparent callbacks and has no transparent draw pass.
Retain those compositor callback contracts; do not add transparent rendering.
NRD/RR previews initially use one primary sample per pixel per frame so guides
match that sample; raw reference may use the full samples-per-pixel range.
The comparison isolates surface lighting: retain existing primary fog/postprocess
integration, disable fog for a clean reference capture where necessary, and do
not claim volumetric or alpha-blended/multiple-transmission ground truth.

Raw PT accumulates high-precision scene-linear radiance with sample count,
resetting for camera/projection/jitter policy, scene/material/light/time changes,
viewport resize, mode switches, world/layer changes and invalid resources.
Use scene generation counters at mutation authorities; animated scenes cannot
silently accumulate different states. NRD/RR previews have their own histories.
Advancing a random sample/jitter sequence does not itself invalidate raw PT;
time-based invalidation applies only when time changes actual shading/geometry,
not unconditionally to the engine clock on every otherwise static frame.
For stable comparison fix exposure and scene time, record SPP/bounce limit and
compare both full lighting and diffuse indirect where meaningful.

## Reconstruction, composition and resource ordering

Hybrid NRD: raster primary export -> RTXDI raw DI -> NRD DI -> compose DDGI
diffuse with primary material exactly once -> emission/sky/fog -> ordinary
upscaler/postprocess. DDGI probe history does not pass through screen NRD.

Hybrid RR: raster primary export -> RTXDI raw DI + DDGI camera diffuse ->
compose noisy HDR with consistent guides/exposure -> RR evaluation instead of
NRD and SR -> remaining retained composition/postprocess at correct resolution.
Keep existing primary fog/sky and compositor callback ordering before the
selected final reconstruction/upscaling slot, then run retained tone mapping.
Preserve the unsupported alpha-material diagnostic; do not add a transparent
pass. Match color/guide coverage; do not tag NRD-packed
normals or normalized light distances as RR guides. Hybrid omits optional
reflection tags, and mode switches explicitly clear formerly tagged PT resources.

PT NRD/RR: feed PT-derived primary guides and valid PT lobe/radiance-distance
signals. Track material modulation conventions separately from raw radiance so
NRD factors are applied once. Reference bypasses both and preserves its own
accumulated HDR output. Mode changes invalidate downstream histories and feature
state before publishing new outputs. No second TAA/SR application after RR.

All scene/feature/cascade mutations occur on rendering ownership threads, with
only copied scalar settings crossing from Environment. RD owns buffer/image,
uniform set, pipeline, SBT and AS lifetimes. Document exact create/free owners
for every addition. Handle partial construction, hot reload, resize, viewport
free, environment switches and shutdown. DDGI trace-read -> blend-write ->
sample-read and PT/DI write -> denoise-read -> composite-read dependencies must
be visible to RD; external Streamline callbacks tag declared RD resources and
use the correct layouts. Release NGX feature resources before recycling IDs.
